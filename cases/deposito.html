Gestión de Depósito Municipal

Una aplicación construida sobre una base PostgreSQL legacy, diseñada para mejorar la operación sin reemplazar de golpe el sistema de datos existente.

Node.jsTypeScriptPostgreSQLReactSecurity
Restricción

El sistema nuevo debía convivir con una base existente.

Productos, stock, entradas, salidas, series y cargos ya vivían en una estructura legacy. La solución debía respetar esa realidad, evitar cambios destructivos y sumar una capa moderna sin romper procesos previos.

Decisión centralAdaptar la aplicación al sistema existente en lugar de forzar una migración total antes de generar valor operativo.
Solución

Capas explícitas y reglas de negocio fuera de la interfaz.

React + Vite + TypeScript
        ↓ HTTP / JSON
Express + TypeScript
        ↓
routes → controller → service → repository
        ↓
Prisma / SQL explícito
        ↓
PostgreSQL legacy + tablas APP_* propias

La aplicación permite consultar y registrar operaciones, buscar por número de serie, administrar usuarios y mantener trazabilidad sobre acciones sensibles.

Seguridad

Identidad y autorización server-side.

  • Roles: ADMIN, RESPONSABLE, OPERADOR y CONSULTA.
  • Sesiones opacas almacenadas en PostgreSQL.
  • Cookie HttpOnly; el frontend no guarda el token de sesión.
  • Contraseñas derivadas con scrypt y salt aleatorio.
  • El backend valida permisos nuevamente en cada request protegido.
  • Auditoría de autenticación, usuarios y movimientos.
Operación

Diseñado para un entorno local real.

El sistema soporta uso LAN de forma opt-in, conserva localhost como comportamiento por defecto y documenta migraciones, instalación y actualización. La evolución es incremental para preservar compatibilidad y recuperación.

La release candidate actual incorpora, entre otras capacidades, remitos PDF para salidas serializadas, búsqueda exacta por número de serie, gestión de usuarios y control de movimientos.

Mi rol

Diseño funcional, técnico e implementación.

Relevé el proceso del depósito, definí arquitectura, permisos y reglas de negocio, implementé backend y frontend, integré la aplicación con la base legacy, diseñé las migraciones propias de seguridad/auditoría y documenté instalación y evolución operativa.

Qué demuestra

Resolver restricciones es parte del trabajo técnico.

  • Integración con una base legacy real.
  • Modelado de roles según responsabilidades operativas.
  • Separación entre UI, reglas y acceso a datos.
  • Auditoría y control de cambios sensibles.
  • Despliegue condicionado por infraestructura local.
  • Evolución sin reescribir todo el sistema existente.
