01 · Arquitectura

Un backend, tres superficies de uso.

El servidor Express expone las interfaces de /recepcion, /medico y /sala. Las acciones operativas modifican el estado persistido en SQLite y los cambios relevantes se distribuyen a las pantallas mediante WebSocket.

La sala usa un payload reducido para mostrar únicamente la información necesaria para el llamado.

Helios XLS/XLSX │ ▼ parser / preview │ ▼ SQLite ◄──── REST / lógica de cola │ └──── WebSocket broadcast ├── /recepcion ├── /medico └── /sala
02 · Estado operativo

El turno se modela como una máquina de estados explícita.

pendiente→ presente→ llamado→ en_consultorio→ atendido
Ausente

Cierra el turno desde los estados habilitados para esa acción.

Volver a cola

llamado → presente; limpia el llamado anterior y libera el consultorio.

Volver a sala

en_consultorio → presente; conserva la llegada y reinicia el ciclo de llamado.

Movimiento

Los turnos pendientes o presentes pueden moverse entre consultorios con validaciones de estado.

03 · Importación Helios

El ingreso de turnos se resuelve sobre archivos exportados.

El importador procesa XLS/XLSX de Helios con una etapa de preview antes del commit. El parser valida columnas requeridas, convierte la fecha serial de Excel, informa errores por fila y agrupa varias filas de prácticas en un único turno.

ParserMódulo puro: recibe un buffer y devuelve grupos listos para preview/commit más errores por fila.
AgrupaciónUna fila por práctica puede convertirse en un turno con múltiples prácticas, preservando orden y evitando duplicados.
Identidad externaSe construye un external_id estable para los registros importados.
AsignaciónLos turnos importados entran en “Sin asignar”. Recepción define manualmente el consultorio físico.
Minimizaciónraw_payload_json conserva únicamente el valor crudo de fecha; el resto de columnas no se replica por defecto.
04 · Interfaces

Cada pantalla expone acciones distintas sobre el mismo estado.

RecepciónRegistra llegadas, asigna consultorio, administra datos operativos y mueve turnos habilitados.
ProfesionalTrabaja sobre la cola del consultorio: llamado, re-llamado, ingreso, retorno a sala y finalización.
SalaRecibe el llamado y presenta nombre, señal sonora y voz sintetizada con una proyección de datos reducida.
05 · Producción

El despliegue también forma parte del sistema.

La instalación productiva es local sobre Windows y no utiliza Docker. El runtime estándar es Node.js portable. El servidor puede ejecutarse como servicio de Windows mediante WinSW, con arranque automático, reinicio ante caídas y logs locales.

ServidorPuerto 3000 dentro de la LAN; acceso por hostname o IPv4 privada.
SalaChrome en modo kiosco abre localhost:3000/sala/ en la PC conectada a la TV.
FirewallRegla de entrada limitada a LocalSubnet; el puerto no se expone a Internet.
BackupCopia consistente de SQLite y adjuntos con procedimiento documentado de restauración.
VersionadoProducción se instala desde un tag estable, no desde main.
