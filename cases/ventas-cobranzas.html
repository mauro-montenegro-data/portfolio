Control Operativo de Ventas y Cobranzas

Un pipeline reproducible que transforma cinco fuentes dispersas en datos validados, registros rechazados, reportes de calidad y evidencia auditable de cada ejecución.

PythonPandasPytestData QualityAuditability
Problema

No alcanzaba con consolidar archivos.

La operación recibe clientes, vendedores, ventas, facturas y pagos por separado. El proceso manual puede arrastrar duplicados, fechas inconsistentes, relaciones rotas, importes incorrectos y pagos sin una factura válida.

La pregunta central¿Cómo producir un dataset utilizable sin ocultar qué fue corregido, rechazado o advertido durante el proceso?
Solución

Pipeline con reglas explícitas y evidencia por corrida.

crear ejecución → detectar archivos → validar estructura → snapshot raw
→ normalizar → validar → separar válidos/rechazados
→ autocorrecciones seguras → processed → quality report
→ manifest → log

Cada ejecución recibe un identificador propio y conserva raw, processed, rejected, errores, quality report, manifest y log.

Resultado

Una corrida de referencia, completamente reproducible.

1.974filas recibidas
1.868procesadas
106rechazadas
1.622observaciones

Dentro de esas observaciones hubo 1.363 autocorrecciones, 149 advertencias y 0 errores bloqueantes en la corrida de referencia. Los datos son 100% sintéticos y se generan con semilla fija.

Criterio

Cuatro severidades distintas.

  • BLOCKING_ERROR: el dataset no puede procesarse de forma segura.
  • REJECTED_ROW: la fila se separa, pero la corrida general continúa.
  • WARNING: el registro se conserva con una condición a revisar.
  • AUTO_CORRECTED: una corrección determinística queda registrada explícitamente.

El objetivo es tolerar datos defectuosos sin convertir cada problema en una falla total y sin perder trazabilidad.

Mi rol

Del caso de negocio a la implementación.

Definí el caso operativo, el modelo de datos, las reglas de validación y la taxonomía de calidad; diseñé el dataset sintético reproducible y la arquitectura modular; implementé el pipeline, tests, reportes y documentación.

Qué demuestra

Datos operativos, no sólo análisis exploratorio.

  • Limpieza y transformación de datos.
  • Reglas de calidad intra-dataset y entre entidades.
  • Reproducibilidad y pruebas automatizadas.
  • Separación entre raw, normalizado, rechazado y reportado.
  • Capacidad de explicar por qué un registro cambió o fue descartado.
